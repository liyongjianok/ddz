# 测试用例

## 1. 测试策略

测试重点：

- 游戏规则正确性。
- 服务端权威。
- 隐藏信息安全。
- 断线重连。

优先级：

1. 规则引擎单元测试。
2. 游戏状态机测试。
3. 房间 Actor 测试。
4. WebSocket 协议测试。
5. API 集成测试。
6. 前端交互测试。
7. E2E 冒烟测试。

## 2. 规则引擎单元测试

### TC-RULE-001 合法牌解析

输入：

- `S3`、`HT`、`DA`、`C2`、`BJ`、`RJ`。

期望：

- 全部解析成功。
- rank 和 suit 正确。

### TC-RULE-002 非法牌解析

输入：

- `X3`、`S1`、`B`、`RJ1`、空字符串。

期望：

- 解析器返回错误。

### TC-RULE-003 牌堆唯一性

期望：

- 牌堆长度 54。
- 无重复牌编码。
- 包含大小王。

### TC-RULE-004 发牌数量

期望：

- 三手牌各 17 张。
- 底牌 3 张。
- 总计 54 张唯一牌。

### TC-RULE-005 单张识别

输入：

- `S3`

期望：

- type 为 `single`，rank 为 `3`。

### TC-RULE-006 对子识别

输入：

- `S3`、`H3`

期望：

- type 为 `pair`。

### TC-RULE-007 三张识别

输入：

- `S3`、`H3`、`D3`

期望：

- type 为 `triple`。

### TC-RULE-008 三带一识别

输入：

- `S3`、`H3`、`D3`、`S4`

期望：

- type 为 `triple_with_single`。

### TC-RULE-009 三带二识别

输入：

- `S3`、`H3`、`D3`、`S4`、`H4`

期望：

- type 为 `triple_with_pair`。

### TC-RULE-010 顺子识别

输入：

- `S3`、`H4`、`D5`、`S6`、`C7`

期望：

- type 为 `straight`，长度 5。

### TC-RULE-011 顺子不能包含 2 或王

输入：

- `ST`、`HJ`、`DQ`、`SK`、`CA`、`D2`

期望：

- 非法牌型。

### TC-RULE-012 连对识别

输入：

- `S3`、`H3`、`S4`、`H4`、`S5`、`H5`

期望：

- type 为 `pair_straight`。

### TC-RULE-013 飞机识别

输入：

- `S3`、`H3`、`D3`、`S4`、`H4`、`D4`

期望：

- type 为 `airplane`。

### TC-RULE-014 炸弹识别

输入：

- `S7`、`H7`、`D7`、`C7`

期望：

- type 为 `bomb`。

### TC-RULE-015 火箭识别

输入：

- `BJ`、`RJ`

期望：

- type 为 `rocket`。

### TC-RULE-016 同牌型比较

输入：

- 单张 4 vs 单张 3。

期望：

- 单张 4 压过单张 3。

### TC-RULE-017 不同非炸弹牌型比较

输入：

- 对 4 vs 单张 3。

期望：

- 不能比较，不能压过。

### TC-RULE-018 炸弹压非炸弹

期望：

- 3 炸弹压过单 A。

### TC-RULE-019 高炸弹压低炸弹

期望：

- 8 炸弹压过 7 炸弹。

### TC-RULE-020 火箭压炸弹

期望：

- 火箭压任意炸弹。

## 3. 游戏状态测试

- TC-GAME-001 初始化游戏：三名玩家、叫分阶段、手牌和底牌正确。
- TC-GAME-002 非当前玩家叫分：返回 `not_player_turn`。
- TC-GAME-003 低于最高分的叫分：返回 `invalid_bid`。
- TC-GAME-004 叫 3 确定地主：进入出牌阶段，地主 20 张，当前回合为地主。
- TC-GAME-005 全部不叫：按策略处理且不死循环。
- TC-GAME-006 非当前玩家出牌：返回 `not_player_turn`。
- TC-GAME-007 出不存在的牌：返回 `invalid_card_set`。
- TC-GAME-008 主动出牌不能不出：返回 `cannot_pass`。
- TC-GAME-009 合法出牌移除手牌、更新 last_play、推进回合。
- TC-GAME-010 响应出牌必须压过上一手。
- TC-GAME-011 两家不出后清理当前 trick，上一手玩家重新主动出牌。
- TC-GAME-012 手牌为空时游戏结束并计算胜方。

## 4. 房间 Actor 测试

- TC-ROOM-001 三人加入：座位 0、1、2 分配，第四人拒绝。
- TC-ROOM-002 同一用户不能重复加入。
- TC-ROOM-003 全员准备后开始游戏。
- TC-ROOM-004 快照隐私：自己的快照有手牌，其他人没有。
- TC-ROOM-005 并发命令不会导致重复开局。
- TC-ROOM-006 超时命令合法且不会在回合变化后重复执行。

## 5. WebSocket 测试

- TC-WS-001 无 token 连接被拒绝。
- TC-WS-002 非法 room 连接被拒绝或返回 `room_not_found`。
- TC-WS-003 成功连接后收到 `room.snapshot`。
- TC-WS-004 未知消息 type 返回 `bad_request`。
- TC-WS-005 ready 消息会广播 ready 事件。
- TC-WS-006 非法出牌返回 error 且状态不变。
- TC-WS-007 私有手牌更新只发送给本人。

## 6. API 测试

- TC-API-001 游客登录返回用户和 access token。
- TC-API-002 `/auth/me` 有效 token 成功，非法 token 拒绝。
- TC-API-003 快速开始返回房间和 WebSocket URL。
- TC-API-004 房间列表不包含牌数据。
- TC-API-005 我的记录只返回当前用户记录。

## 7. 重连测试

- TC-REC-001 断线后标记离线并广播。
- TC-REC-002 重连后恢复本人当前手牌。
- TC-REC-003 重连快照不泄漏他人手牌。
- TC-REC-004 离线期间超时动作执行，重连后看到更新状态。

## 8. 机器人测试

- TC-BOT-001 机器人叫分合法。
- TC-BOT-002 机器人出牌合法。
- TC-BOT-003 机器人不会出手牌外的牌。
- TC-BOT-004 无合法响应时机器人不出。
- TC-BOT-005 机器人补齐空座。

## 9. 前端测试

- TC-FE-001 游客登录保存 token 并进入大厅。
- TC-FE-002 大厅快速开始进入房间。
- TC-FE-003 房间快照渲染座位、手牌、阶段、回合和倒计时。
- TC-FE-004 点击卡牌切换选中态。
- TC-FE-005 非当前回合禁用出牌/不出。
- TC-FE-006 重连 UI 显示并在快照后恢复。

## 10. E2E 冒烟测试

### TC-E2E-001 三个真人客户端完成一局

期望：

- 三个客户端登录、加入同房间、准备、完成对局并看到结算。

### TC-E2E-002 一人两机器人完成一局

期望：

- 真人快速开始，机器人补位，对局完成。

### TC-E2E-003 游戏中刷新

期望：

- 浏览器刷新后重连并恢复游戏。
