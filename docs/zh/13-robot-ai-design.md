# 机器人 AI 设计

## 1. 目的

机器人用于：

- 单人也能立即开始游戏。
- 自动补齐空座。
- 玩家断线时根据策略执行超时动作。

机器人必须始终产生合法动作。牌技强弱是次要目标，正确性优先。

## 2. 机器人类型

### 2.1 补位机器人

房间真人不足时使用。

行为：

- 延迟加入等待房间。
- 自动准备。
- 完整参与对局。

### 2.2 离线托管机器人

玩家游戏中断线时使用。

行为：

- 只在超时后行动。
- 除非配置允许，不立即全权接管。
- 玩家重连后恢复控制权。

## 3. 设计原则

- 机器人动作进入房间命令队列。
- 机器人使用和真人相同的校验路径。
- 机器人不能直接修改游戏状态。
- 机器人只能看到自己座位信息和公开状态。
- 固定 seed 下策略应可确定，方便测试。

## 4. 机器人输入快照

```go
type RobotSnapshot struct {
    RoomID string
    GameID string
    SeatIndex int
    Role Role
    Phase GamePhase
    Hand []Card
    PublicPlayers []PublicPlayerState
    BottomCards []Card
    CurrentSeatIndex int
    LastPlay *Play
    Multiplier int
    BidState BidStateView
}
```

隐私：

- 机器人获得自己的手牌。
- 机器人不能获得其他玩家隐藏手牌。

## 5. 机器人动作

```go
type RobotAction struct {
    Type RobotActionType
    BidScore int
    Cards []Card
}
```

动作类型：

- `bid`
- `play`
- `pass`

## 6. 叫分策略

MVP 启发式：

计算手牌强度：

- 火箭：+8。
- 每个炸弹：+6。
- 每张 2：+2。
- 每张王：+3。
- 每张 A/K：+1。
- 长顺子或飞机：+2。

决策：

- 强度 >= 16：能叫 3 则叫 3。
- 强度 >= 12：能叫 2 则叫 2。
- 强度 >= 8：能叫 1 则叫 1。
- 否则不叫。

若当前最高叫分已更高：

- 只有期望分数大于最高分才叫。
- 否则不叫。

## 7. 出牌策略

### 7.1 主动出牌

优先级：

1. 如果一手能出完，直接出完。
2. 手牌弱时优先出最小单张。
3. 优先打出能降低手牌复杂度的低牌组合：
   - 顺子。
   - 连对。
   - 不带牌飞机。
   - 三带。
   - 对子。
   - 单张。
4. 不到残局尽量保留炸弹和火箭。

### 7.2 响应上一手

优先级：

1. 有非炸弹合法响应时，出最小能压过的牌。
2. 对手剩牌很少时，可考虑炸弹。
3. 自己是农民且上一手来自另一个农民时，优先不出。
4. 其他情况能不出则不出。

MVP 中队友意识可以简单处理：

- 机器人是农民，上一手也是农民打出时，优先 pass。

### 7.3 残局启发

如果机器人本轮能获胜：

- 出获胜牌型。

如果下家只剩 1 张：

- 主动出牌时尽量出对子或更大组合，避免单张。

如果下家剩 2 张：

- 尽量避免主动出对子。

## 8. 合法动作依赖

机器人必须调用：

```go
LegalResponses(hand, previous)
Recognize(cards)
CanBeat(candidate, previous)
```

不得另外手写一套可能和规则引擎分叉的合法性逻辑。

## 9. 动作时机

机器人动作延迟：

- 最小：500 ms。
- 默认：1,000 到 2,500 ms 随机。
- 超时托管动作：超时命令后立即或 300 ms 内执行。

不要在房间 Actor 内 sleep。

实现方式：

- Actor 外部调度 timer。
- timer 发送机器人命令进入 Actor 队列。

## 10. 难度

MVP：

- `basic`

未来：

- `easy`：更随机、更弱。
- `normal`：启发式。
- `hard`：搜索型。

## 11. 测试

必需测试：

- 机器人叫分合法。
- 机器人随机手牌出牌合法。
- 机器人不会出手牌外的牌。
- 无合法响应时机器人不出。
- 主动出牌合法。
- 固定 seed 下确定。

推荐性质测试：

- 生成随机手牌和上一手。
- 请求机器人动作。
- 使用规则引擎验证。

## 12. 机器人验收标准

- 真人可以和两个机器人完成一局。
- 机器人不会导致非法游戏状态。
- 机器人遵守隐藏信息边界。
- 离线托管不影响玩家重连接管。
